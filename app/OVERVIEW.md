## 一、做了什么

一个可被 AI 直接操作的网页剪辑台。本期（M1）交付你最要的四件事：**时间线、拖拽素材、剪切、拼接**，
外加一件我判断必须先做的事：**命令层**。

| 能力 | 状态 | 说明 |
|---|---|---|
| 素材导入 | ✅ | 拖入/选择本地文件，服务端 ffprobe 探测时长分辨率 + ffmpeg 抽缩略图 |
| 多轨时间线 | ✅ | V1 主视频 / V2 覆盖层 / A1 音频，标尺、播放头、缩放 |
| 拖拽素材上轨 | ✅ | 从素材库拖到任意轨道，落点由鼠标位置决定 |
| 拖动改位置 | ✅ | 拖动片段本体，自动吸附片段边缘与播放头 |
| 裁剪 | ✅ | 拖左右边缘改入出点，不会压到相邻片段 |
| 剪切（分割） | ✅ | 播放头定位 + `S` / 点按钮；也可双击片段就地分割 |
| 拼接 | ✅ | 一键把轨道片段左对齐、首尾相接 |
| 预览播放 | ✅ | 单播放器换源，跨片段连续播放，自动跳过空隙 |
| **命令 API** | ✅ | `POST /api/commands`，AI 与 UI 走同一套命令 |
| **远端操作可见** | ✅ | AI 从外部改的东西会以「远端 · xxx」出现在命令台 |
| **按路径原地导入** | ✅ | 直接引用别的工程（漫剧）磁盘上的片段，不复制文件 |
| **素材分组** | ✅ | 按第一层文件夹名自动分组（漫剧的 E01–E12 一进来就是分好的） |
| **一集铺满时间线** | ✅ | 一个调用完成「导入 → 挑正片 → 清轨 → 逐条上轨 → 拼接」 |
| **单端口对外** | ✅ | 后端顺便托管前端产物，只暴露一个地址，方便被当外部平台调用 |
| 导出 MP4 | ⛔ 按你的决定推迟 | M2 |
| 自然语言 → 命令 | ⛔ M3 | 本期只做结构化命令 |

## 二、核心决策：为什么先做命令层

你原话是「让 AI 操作的网页工作台」。这里有个岔路口：

- ❌ 做法 A：先做个网页版剪映，以后让 AI 去模拟鼠标点击 → 脆、慢、状态看不见，迟早推倒重来
- ✅ 做法 B：**先把剪辑动作抽象成命令，网页只是命令层的一个视图**

选了 B。落到代码上就是：所有编辑都是命令（`addClip` / `moveClip` / `trimClip` / `splitClip` / `deleteClip` / `concatTrack`），
鼠标拖拽和 AI 指令走**同一条总线**，拖拽过程中只改本地显示、松手才发一条命令。

好处已经兑现：验证时我用 curl 从外部发了一条 `splitClip`，**页面没刷新**，V1 从 2 段变成 3 段，
命令台里同步出现「远端 · 拼接轨道 V1」。这就是「可被 AI 操作」的实证。

**关键设计**：`Asset` 不可变，`Clip` 只持有 `{ assetId, start, in, out }` 引用。
一份素材可以切成 10 段放 10 个位置，磁盘上只有一份文件 —— 这是剪切和拼接能成立的基石。

## 三、怎么跑起来

```bash
npm install        # 首次装依赖（npm 慢就加 --registry=https://registry.npmmirror.com）
npm run samples    # 生成三份演示素材（可选，没素材可拖时先跑）
npm run dev        # 后端 4000 + 前端 5173
```

打开 http://localhost:5173

**让 AI 操作它**：

```bash
curl -s -X POST localhost:4000/api/commands \
  -H 'Content-Type: application/json' \
  -d '{"commands":[{"type":"concatTrack","trackId":"V1"}],"source":"ai"}'
```

页面会立刻跟着变。

### 过程中修掉的两个真问题

1. **Fastify 的 `setErrorHandler` 必须写在注册路由之前**。子上下文创建时会快照父级错误处理器，
   写在后面的话路由仍然走默认处理器 —— 表现是越界分割本该返回 `422 SPLIT_OUT_OF_RANGE`，实际吐了个 500。
   这个坑只靠读代码看不出来，是冒烟测试逼出来的。
2. **播放头落进片段之间的空白会卡死**。原来的换源逻辑只在「片段结束 → 下一片段紧邻」时前进，
   有空隙就停在那儿不动。改成找「下一个有画面的时刻」，跳过空隙。

## 五、工程实践落地情况

**照规范做了**：配置全部走环境变量并在启动时校验（写错直接起不来）、类型化错误 + 全局错误中间件（客户端只看得到
`{code, message, requestId}`，没有堆栈）、结构化 JSON 日志贯穿 requestId、zod 校验所有输入边界、
`/health` `/ready`、优雅停机、CORS 显式白名单、安全响应头、控制器/服务/仓储三层分离。

**刻意没做**（避免过度设计）：数据库（工程状态一个 JSON 文件 + 原子 rename，零迁移成本）、认证、Redis、Docker。

**一处刻意的偏离**：规范说「5xx 自动重试最多 3 次」，我只对**读**操作重试。
`POST /api/commands` 绝不自动重试 —— `addClip` 不是幂等的，重试会凭空多出一个片段。
拿一致性换那点可用性不划算。代码里有注释说明。

## 七、追加：作为外置剪辑系统接入漫剧工程（同日）

—— `SKILL.md` + `references/{app,launcher,api}`。

### 与漫剧工程的对接结论

**分进程，不合并。** 漫剧工作台是 Python 3.13 + ffmpeg/PIL 的常驻批处理；剪辑台是 Node 22 + 浏览器端
60fps 时间线。合并会卡 —— 那边跑一批生视频时 CPU 打满，浏览器的时间线渲染和视频解码会被抢掉，
拖片段就开始掉帧；而且一个进程管两种运行时很脆，编辑器崩了还会把正在跑的任务带走。
分进程后由系统调度器隔离，唯一的「合」是数据（都读同一批文件，本机磁盘，无同步问题）。

### 为此新加的能力

| 能力 | 说明 |
|---|---|
| `POST /api/assets/import` | 按路径原地导入，**不复制文件**，按第一层文件夹名自动分组，幂等 |
| 素材库分组 UI | 按组折叠、组内拖拽、每组「整组加入」到主视频轨 |
| 单端口模式 | `npm run build` 后后端托管前端产物，只暴露 `127.0.0.1:4000` |
| 一键铺时间线 | `jianyingcut_client.py episode <片段目录> E01` 一次完成导入→挑正片→清轨→上轨→拼接 |
| 启动器 | `启动剪映Cut.command` 双击即用，`jianyingcut.conf` 里配端口与自动导入目录 |

### 实测（用你真实的漫剧工程数据跑的）

- 导入 `02_数据/05_视频片段`：**75 个片段，0 失败**，自动分成 E01:17 E02:5 E03:3 E04:3 E05:8 E06:8 E07:9 E08:6 E10:6 E11:6 E12:2
- 静态服务返回 **206 Range**（视频拖进度条必须有）；缩略图已生成；路径穿越被 404 挡；`/etc` 导入返回 **403** 并附允许目录清单
- `episode E01` → E01 是镜级命名，挑出 **15 段 76.32s** 铺满 V1
- `episode E05` → E05 是组级命名（`_G01_whole12s`），auto 模式自动退到组级，**8 段 79.52s**
- `episode E05 --mode shots` → 报错并说清该组是组级命名（不静默吞掉）
- 回归：领域自检 12/12、端到端冒烟 11/11、三包类型检查 0 错误、vite build 通过

### 命名约定（客户端已内建）

```
E01_S001.mp4 … E01_S015.mp4        镜级（一镜一条）
E05_G01_whole12s.mp4 …             组级（九宫格整段生成）
*_multiframe / *_测试* / *_误存* / *_无音频版   调试返工产物，不算正片
```

实测同一个工程里**两种约定并存**（E01 镜级、E05 组级），所以 `mode=auto` 的语义是
「有镜级用镜级，没有才退组级」。

### 漫剧工作台的「剪辑台」按钮（已加）

加在**项目里那份**工作台源码上 —— 也就是实际运行的那份：
`~/WorkBuddy/2026-10-05-17-28-54/01_代码/workbench/`
（**不是**桌面工具目录里的 `engine/`，那只是由「更新引擎.command」同步过去的副本）

| 文件 | 改动（全是增量） |
|---|---|
| `index.html` | topbar 里加了一个 `#btnJianyingCut`（在 AI 按钮之后，同样式、同样带状态指示灯） |
| `app.js` | state +2 字段；+3 个函数（`renderJianyingCutChip` / `refreshJianyingCut` / `jianyingcutOpen`）；bindEvents +1 绑定；启动段 +1 次状态刷新 |
| `app.py` | +1 个 GET 接口 `/api/jianyingcut` + 4 个 `jyc_*` 辅助函数（`import time`、`quote`） |

**接口行为**

- `GET /api/jianyingcut` → 只查状态（快），给顶栏指示灯用
- `GET /api/jianyingcut?want=open` → 没在跑就拉起启动器并轮询到就绪，返回可直接打开的地址
- `POST /api/jianyingcut/close` → 关掉。优先跑它自己的停止脚本，退不掉再按端口兜底
  （兜底前会再确认那端口上确实是自家服务，避免误杀）。关掉是有副作用的动作，所以用 POST
- 片段目录**读 `project.json` 的 `paths.clips`**（路径唯一真相源，不写死目录名）
- 返回的 URL 自带 `?import=<片段目录>`，所以打开就是「左边按集分好的素材」
- 照抄工作台里已有的先例：本机回环请求**绕开系统代理**（`ProxyHandler({})`），
  否则连不上会拿到错误页而不是异常，会被误判成「服务正常」

**按钮是个开关**

| 点的时候 | 行为 |
|---|---|
| 未运行 | 直接拉起 + 打开页面（拉起中按钮禁用，指示灯转圈） |
| 已在运行 | 弹三选项：**打开页面** / **关闭剪辑台** / 取消 |

为此给通用确认框 `wbConfirm` 加了个可选参数 `altText`：给了就多一个中间按钮，
`resolve` 出字符串 `'alt'`；不给就显式隐藏。**这是通用能力，别处也能用。**

**实测**：四条分支全过 —— 未运行时点击能拉起并打开；运行中点击弹三选项；
选「关闭剪辑台」→ 灯转黄、toast「剪辑台已关闭」、端口释放（1.1 秒）；选「打开页面」→ 新标签打开且服务不受影响；
取消不动任何状态。

### 顺手修掉一个既有 bug（不是这次引入的）

`.wb-cfm-field{display:flex}` 和 `.btn` 的 `display` **盖过了浏览器默认的 `[hidden]{display:none}`**，
所以只写 `hidden` 属性根本藏不住 —— **所有确认对话框（重启/关闭/切项目/新建项目）里都挂着一个多余的空输入框**。
加了两行 CSS 修掉（`.wb-cfm-field[hidden]` / `.btn[hidden]`），写法照这个文件里已有的同类规则来。

> 这个坑值得记住：**`[hidden]` 只在没有任何显式 `display` 时才生效**。
> 项目里已经为 `.wb-dlg` / `.pg-selbar` / `.cs-dragbar` 等补过同样的规则，漏了 `.btn` 和 `.wb-cfm-field`。

**改之前先确认跑的是哪份代码**：桌面工具目录的 `engine/` 和项目 `01_代码/` 里的工作台是**两份**，
且差异很大（app.js 差 1.5 万行）。第一次改错了副本 → 接口 404，
靠「进程 cwd + 接口 404」才定位到真正在跑的是项目那份。

**原件备份**：`Desktop/06 工具与脚本/一站式ai漫剧工具/.backup-剪辑台改动-20261013/`（含逐条还原说明）。

## 八、遗留与建议

| 项 | 说明 |
|---|---|
| 预览换源瞬间有极短跳变 | 没做双播放器预载，M2 处理。不影响剪辑操作 |
| 命令台没做撤销 | 状态树是按可快照的方式组织的，undo/redo 接上去几乎是白送，建议早做 |
| V2 覆盖层只存不合成 | 目前 V2 上的片段在预览里不参与合成（M1 只做多轨显示 + 单轨播放） |
| 属性面板高度偏紧 | 已可滚动，但不舒展，属于打磨项 |
| 未做鉴权 | 服务只绑 `127.0.0.1`，本机工具定位。要给别人用必须先加访问控制 |

**下一步建议顺序**：撤销重做 → 导出 MP4（ffmpeg 拼接 + 任务队列 + 进度）→ 自然语言 → 命令（接一个 LLM 做翻译层）→ 多轨合成。
