# 剪辑台接入 WorkBuddy —「信任」与「关闭按钮」排查结论

日期：2026-10-14　范围：`jianyingcut`（剪映Cut）连接器 / 漫剧工作台

---

## 一、「信任」这一步：确实还没完成，且只能你自己点

**现状**

- `~/.workbuddy/mcp.json` 里 `jianyingcut` 已注册（stdio，`disabled: false`，指向
  `~/.workbuddy/mcp-servers/jianyingcut-mcp/jianyingcut_mcp.py`）。
- 但本会话的工具清单里**没有 `jc_*`**（按名精确查找未命中）→ 连接器尚未生效。

**为什么**

新装的自定义 MCP 服务器需要**本人在客户端点一次「信任」**，而且点完**还要新开一个会话**
（或重启客户端）才会把工具挂上来 —— 正在进行中的会话看不到它们。

**位置**

对话窗口 → 连接器管理 → 右上角「自定义连接器」入口 → 找到 `jianyingcut` → 点 **信任** → 新开一个会话。

**我为什么不代点**

这是客户端里的安全同意动作（等于授权一个本机程序让 AI 随意调用），必须由本人确认。而且它
**不落在任何磁盘配置里** —— 已查过 `~/.workbuddy/app/app-config.json`、各账号目录下的
`connector-states*.json`、客户端的 Local Storage / IndexedDB，都没有相关信息；客户端界面
本身是远端加载的（`app.asar` 里 6 处「控制台」全是日志 SDK 文档，没有 UI 文案）。所以没有
可靠、正当的途径替你勾选。

## 二、不点信任也能用（已实测跑通）

**MCP 只是三条通路里的一条**，只有它需要信任：

| 通路 | 需要信任 | 实测结果 |
|---|---|---|
| MCP 连接器 `jc_*` | 是 | 本会话不可用 |
| 技能内直连客户端 `jianyingcut_client.py` | 否 | ✅ `未命名工程 · rev 4 · 素材 75 个`；V1 0 段 / V2 1 段 5.1s / A1 0 段 |
| 裸 HTTP API | 否 | ✅ `GET /api/jianyingcut` → `running=true, rev=4, clips_dir 存在` |

```bash
# 读状态
python3 ~/Desktop/06 工具与脚本/剪映Cut/api/jianyingcut_client.py state

# 把某集铺到时间线并拼接
python3 ~/Desktop/06 工具与脚本/剪映Cut/api/jianyingcut_client.py \
        episode "/Users/caoyouqing/WorkBuddy/2026-10-05-17-28-54/02_数据/05_视频片段" E01 --track V1

# 下发一条剪辑命令
python3 ~/Desktop/06 工具与脚本/剪映Cut/api/jianyingcut_client.py \
        cmd '{"type":"splitClip","clipId":"…","at":3.5}'
```

结论：**「让 AI 操作剪辑台」这件事现在就能做**，连接器只是让人在 WorkBuddy 里用自然语言叫得动它，
属于体验优化，不是前置条件。

## 三、没找到「关闭视频控制台程序」这个字面按钮

全盘检索（工作台源码、桌面工具目录、客户端包、客户端本地存储）**不存在**「视频控制台」或
「关闭视频控制台程序」这个文案。按语义最接近的是这三个真实按钮：

| 位置 | 按钮 | 实际作用 | 端点 |
|---|---|---|---|
| 漫剧工作台顶栏（红） | **关闭** | 先终止所有后台任务，再关闭工作台进程，不留残留 | `POST /api/console/server/shutdown` |
| 漫剧工作台顶栏 | **重启** | 终止任务 → 重启进程 → 约 3.5 秒后自动刷新页面 | `POST /api/console/server/restart` |
| 漫剧工作台顶栏「剪辑台」 | **二次点击** | 弹三选一：取消 / 关闭剪辑台 / 打开页面 | `POST /api/jianyingcut/close` |

⚠️ 关键区别：这几个关的是**漫剧工作台**或**剪辑台**，
跟「让 MCP 信任生效」**无关** —— 信任要生效得重启的是 **WorkBuddy 客户端本身**（或直接新开一个会话）。
