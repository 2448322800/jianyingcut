# AI 剪辑工作台 · 项目计划 v0.1

> 定位：一个 **AI 能直接操作** 的网页版剪辑台。交互与视觉对标剪映桌面版 / ChatCut。
>
> **状态：M1 已交付并实测通过。** 交付总结见 `OVERVIEW.md`，运行方式见 `README.md`。

---

## 一、目的（为什么做）

**现状**：剪映是给人用的。AI 想剪辑只能模拟鼠标点击——脆弱、慢、还看不清状态。

**目标**：把所有剪辑动作抽象成一套**命令**。UI 点按钮 = 发命令，AI 发指令 = 发同一条命令。唯一真源是一棵状态树。

**一句话验收**：
> AI 发一条指令 → 时间线自动变化 → 秒级可预览 → 一键导出 MP4。

**核心架构分水岭**：
不是「先做个网页版剪映，以后想办法让 AI 用」，而是**「命令层先行，网页只是命令层的一个视图」**。这个顺序反了就要推倒重来。

## 二、页面参考与布局

对标剪映（分区逻辑）+ ChatCut（AI 指令位），五个分区：

| 分区 | 位置 | 职责 | 数据来源 |
|---|---|---|---|
| 素材库 | 左上 | 资产的「仓库」：导入、预览、拖出去 | `Asset[]` |
| 预览 | 中上 | 播放头处的画面 | 时间线派生 |
| 属性 | 右上 | 选中 clip 的参数 | 选中项 |
| AI 指令条 | 中下 | **命令入口**，与鼠标拖拽平级 | `dispatch(command)` |
| 时间线 | 底部 | 核心工作区：多轨、拖动、剪切、拼接 | `Track[]` → UI |

**时间线轨道设计**：V1（主视频轨，承载拼接）/ V2（覆盖层：字幕、贴纸）/ A1（音频）。M1 只实现 V1 的完整能力，V2/A1 先做「能放、能显示、能拖动」，合成留到 M2。

**交互（对标剪映）**：
- 素材从素材库拖到轨道 → 落点由鼠标 x 决定
- 拖动 clip 本体 → 改在时间线上的位置
- 拖动 clip 左/右边缘 → 改入点/出点（裁剪）
- 播放头定位 + 分割 → 一刀两段
- 吸附：clip 边缘互相吸附 + 吸附播放头

## 三、本期范围（M1）

### ✅ 做
1. **素材导入**：本地文件拖入/选择 → 素材库，自动读取时长、分辨率、生成缩略图
2. **拖拽上轨**：素材 → 任意轨道，落点定位
3. **时间线操作**：拖动改位置、拖边缘改时长、删除
4. **剪切**：播放头定位 + 分割（`S` 键 / 剪刀按钮），一刀两段，两段独立可编辑
5. **拼接**：同轨道按顺序首尾相接，预览连续播放
6. **预览**：播放 / 暂停 / 拖动播放头 / 逐帧，画面与时间线严格同步
7. **命令 API**：HTTP 命令口 + SSE 广播，AI 发的命令前端自动同步（本期核心增量）
8. **命令控制台**：命令流日志 + JSON 命令输入，用于验证命令链路的端到端可用

### ❌ 明确不做（推迟，避免过度设计）
- ~~导出 MP4~~（**用户决定：推后**，M1 拿不到成片，验收只到预览）
- 自然语言 → 命令（M3，需要 LLM，本期只做结构化命令）
- 转场、滤镜、调色、变速、关键帧动画
- 多轨画面叠加合成（M2）
- 字幕编辑器、贴纸库、音频波形/闪避
- 云工程、多人协作、账号体系、权限
- 移动端适配
- 撤销/重做（M2 补，但状态结构一开始就为它预留）

## 四、工程实践

### 4.1 架构：命令层是核心

```
UI 事件 ──┐
          ├──→ 命令总线 dispatch ──→ Reducer ──→ 状态树 ──→ 渲染
AI 请求 ──┘                                      │
                                            快照栈（undo/redo 预留）
```

所有编辑都必须是命令，**禁止在组件里直接改状态**：

```
addAsset · addClip · moveClip · trimClip · splitClip · deleteClip
· concatTrack · setPlayhead · undo · redo
```

每条命令携带 `{ type, payload, source: 'user' | 'ai' }`。
`source` 字段用于日志、审计和「AI 操作高亮」——AI 改了什么，用户能看见。

### 4.2 数据模型（草案）

```ts
Project { id, name, fps, width, height, tracks: Track[] }
Asset   { id, name, src, duration, width, height, thumb }   // 原始素材，不可变
Track   { id, type: 'video' | 'audio', clips: Clip[] }
Clip    { id, assetId, start, in, out }    // start=时间线位置  in/out=素材裁剪点  duration=out-in
Command { type, payload, ts, source }
```

**关键设计**：`Asset` 不可变 + `Clip` 持有 `in/out` 引用。
同一素材可以被切成 10 段、放 10 个位置，磁盘上只有一份文件。这是拼接和剪切的基石。

### 4.3 目录结构（按功能组织 + 三层）

```
server/
  src/
    config/         环境变量集中校验，启动即快速失败
    shared/         类型化错误、日志、中间件、zod 校验
    media/          素材：上传 → 探测元数据 → 生成缩略图
    project/        工程状态 + 命令执行
    export/         导出任务：队列 + ffmpeg 拼接
  media/            上传的素材与产物（gitignore）
web/
  src/
    core/command-bus/     ← UI 与 AI 共用的唯一入口
    core/api/             类型化 fetch 封装，Base URL 走环境变量
    core/store/           状态树 + reducer
    features/media/       素材库
    features/preview/     预览播放器
    features/timeline/    时间线（组件 + 选择器）
    features/inspector/   属性面板
```

### 4.4 工程规则（沿用全栈规范，但克制）

**必须**：
- 配置全部来自环境变量，启动时校验，格式错误直接起不来；只提交 `.env.example`
- 类型化错误 + 全局错误中间件；客户端永远看不到堆栈
- 结构化 JSON 日志，贯穿 requestId；不记录文件内容
- 所有输入边界校验（zod），不信任前端
- `/health` `/ready` 健康检查 + 优雅停机
- CORS 显式来源白名单，不用通配符
- **导出这种长任务绝不放在请求处理器里**：入队，返回 taskId，前端轮询/SSE 拿进度
- 前端：API 错误映射为可读文案；4xx 不重试，5xx 最多重试 3 次

**克制项（M1 不引入）**：数据库（工程状态落 JSON 文件）、认证体系、Redis、Docker、微服务。

### 4.5 关键技术取舍

| 问题 | 选择 | 理由 |
|---|---|---|
| 时间线渲染 | DOM + 绝对定位 | 几十个 clip 足够，拖拽/命中/调试都最简单；上千 clip 再换 canvas |
| 预览播放 | 单个 `<video>` + 播放头驱动换源 | 简单可靠；多轨合成是 M2 的事 |
| 帧同步 | `requestVideoFrameCallback` 校准 | 避免 `timeupdate` 粗粒度导致的累积漂移 |
| 导出拼接 | 后端 ffmpeg（已内置本机） | 快、稳、内存友好，支持任意大小；wasm 大文件会崩 |
| 状态管理 | 轻量 store + 快照式历史 | 命令层天然可快照，undo/redo 几乎白送 |
| 素材探测 | ffprobe 读时长/分辨率 | 比前端 `<video>` 试探准确，且要做缩略图 |

## 六、验收标准（M1 完成定义）

每条都必须可实测：

1. 拖 3 个 mp4 进素材库 → 3 秒内出现缩略图与时长
2. 拖到 V1 → 顺序排列 → 播放时画面连续，无黑屏、无跳帧
3. 播放头停在中间按分割 → 一条变两条，两段可分别拖动、删除、再裁剪
4. 点导出 → 得到 MP4，时长 = 时间线总长，顺序与预览完全一致
5. **（关键）** 一条 AI 命令（如「剪掉第一段前 2 秒」）能真实改变时间线 —— 证明命令层已打通

第 5 条是本期真正的成败判据：它证明这个工作台「可被 AI 操作」，而不只是一个网页播放器。

## 七、已确认决策（2026-10-13）

| 决策 | 结论 | 对 M1 的影响 |
|---|---|---|
| 导出 MP4 | **本期不做**，推迟到 M2 | 后端不含 ffmpeg 拼接与任务队列 |
| AI 操作形态 | **命令 API 先行** | M1 交付 `POST /api/commands` + `GET /api/events`(SSE)，AI 改的工程前端自动同步 |
| 素材来源 | **本地上传** | 上传到 `server/media/`，服务端 ffprobe 探测 + ffmpeg 抽缩略图 |

**技术栈（已定）**：前端 React 19 + TypeScript + Vite + Zustand；后端 Node 22 + Fastify + TypeScript + zod；
无数据库（工程状态落 JSON 文件）；样式手写 CSS 变量，不引 Tailwind（时间线需精确 px 计算）。

**同步模型**：前端本地状态是 UI 真源（保证拖拽跟手），命令批次异步 POST 到后端持久化并广播；
AI 或其它客户端发来的命令经 SSE 下发，前端在非交互态应用。命令带 `source: 'user' | 'ai'` 区分来源。
